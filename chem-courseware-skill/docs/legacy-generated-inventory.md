# Legacy Generated Inventory

This inventory separates the active V1 workflow from older generated/reference files.

## Active V1 workflow

Use this path as the default mental model for agents and maintainers:

1. `semantic-draft.json`
2. `scripts/compile-semantic-draft.mjs`
3. `<slug>.hud.html`, `<slug>.scene.js`, `<slug>.meta.json`
4. `scripts/assemble-courseware.mjs`
5. `generated/<kind>/<slug>/index.html`
6. Playwright verification

Anything outside that flow is not automatically part of the current contract.

## Delete or archive candidates

Do not delete blindly. A file becomes a delete/archive candidate only when all of these are true:

- no test depends on it
- no skill/docs/scripts reference it
- it can be regenerated by the active compiler/assembler pipeline
- it is not the only working example of a specific interaction pattern

## Quarantine rule

- Do not treat `generated/` as a single homogeneous workspace.
- Prefer `examples/` for stable manual fixtures.
- Prefer `examples/drafts/` for compiler inputs.
- Prefer `generated/<kind>/<slug>/` only for outputs created by the active assembler contract.
- Prefer `generated/legacy/` for quarantined standalone references.
- Treat older `generated/<kind>/<slug>/index.html` files as legacy references until they are explicitly rebuilt through the active pipeline.
- Treat nested trees like `generated/experiment/experiment/<slug>/...` as stale artifacts, not canonical outputs.
